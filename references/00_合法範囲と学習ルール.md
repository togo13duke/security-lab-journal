# 合法範囲と学習ルール

## 結論

フェーズ0では「自分が所有する環境」「明示的に許可された演習環境」「公開された教育用CTF」だけを対象にする。これを外れた行為は学習ではなくリスク。

## 許可される対象

- 自分のPC、ローカルVM、ローカルDockerコンテナ
- 自分で作ったWebアプリ、API、検証用サーバ
- OverTheWire、PortSwigger Web Security Academyなどの教育用演習環境
- Hack The Box Academy、TryHackMeなど、利用規約上許可された演習環境
- 所属組織や顧客から書面で許可された検証対象

## 許可されない対象

- 許可のないWebサイト、API、クラウド環境、社内ネットワーク
- 他人のWi-Fi、端末、アカウント
- 実在サービスへのスキャン、ブルートフォース、脆弱性検証
- 演習環境の認証情報、解答、フラグの公開

## 判断基準

次の3つに全部 yes と答えられないなら止める。

1. 対象の所有者または運営者から明示的な許可があるか。
2. 許可範囲、時間、手法、影響上限が明確か。
3. ログ、証跡、再現手順を説明できるか。

## ログの原則

- 実行したコマンド、目的、対象、結果、次の判断を残す。
- 失敗も記録する。失敗ログは後で最も価値が出る。
- 認証情報、個人情報、第三者の秘密は保存しない。

## 反対意見と代替案

反対意見：実サービスに触らないと現場感が出ない。

回答：フェーズ0では現場感より基礎の再現性が重要。現場感はフェーズ1以降に、Bug bountyのスコープや正式な許可付き検証で扱う。代替案として、PortSwigger Academy、OverTheWire、自作ローカル環境を使う。
