## 最適判断

今日の最適解は、派手なセキュリティ演習ではなく、Pythonでローカルの学習ログをMarkdownに整形する小スクリプトを作ること。理由は3つある。

第一に、水曜テーマと一致する。3か月カリキュラムは水曜をPythonの日としており、20〜50行の小スクリプトが最低ラインになっている。

第二に、明日の重ラボの成功率を上げる。明日のカレンダーは「構築、解析、コーディング、またはWireshark/SIEM調査を1ステップ前進」としているが、最後にログを書くことが必須になっている。今日ログ整形の型を作っておけば、明日は作業結果を記録に落としやすい。

第三に、合法範囲が明確。ローカルのテキストファイルだけを扱うため、外部対象へのスキャン、侵入、認証回避、エクスプロイト送信といった禁止領域に触れない。

反対案は、明日の「重ラボ」を今日から前倒ししてWiresharkやHTTP観察まで進めること。メリットは進捗が大きい点。デメリットは、今日のカレンダーに学習枠がない状態で範囲が広がり、ログの型がないまま作業だけが残るリスクが高い点。今日は採用しない。

代替案は、Linux/Gitだけに絞ってコマンドチートシートを作ること。メリットは確実に完了しやすい点。デメリットは水曜テーマのPythonを外す点。最低メニューとしては有効だが、標準案では採用しない。

- 今日の対象はローカルファイルだけに限定する。

labs/sandbox/python-log-formatter/format_log.py

### 1. 作業環境確認 10分

次を実行し、ラボノートに結果を書く。

```sh
git status
python3 --version
pwd
mkdir -p labs/sandbox/python-log-formatter
```

記録する観点：

- Python 3が使えるか。
- 作業場所がリポジトリ内か。
- Gitで差分を確認できる状態か。

### 2. 入力ファイル作成 10分

ローカルのサンプルログを作る。実在サービスのログ、個人情報、認証情報は入れない。

```sh
cat > labs/sandbox/python-log-formatter/sample.log <<'EOF'
2026-06-03T10:20:00 command=git_status result=ok note=checked_worktree
2026-06-03T10:25:00 command=python_version result=ok note=python3_available
2026-06-03T10:30:00 command=create_sample_log result=ok note=local_only
EOF
```

観察する項目：

- 1行に時刻、操作、結果、メモが含まれているか。
- 秘密情報や第三者情報が含まれていないか。
- 後からMarkdownに変換しやすい形か。

### 3. Pythonスクリプト作成 25分

20〜50行を目安に、ログをMarkdown表へ変換する。

```sh
$EDITOR labs/sandbox/python-log-formatter/format_log.py
```

最低限の仕様：

- `sample.log` を読む。
- 各行を空白で分割する。
- `command=...`、`result=...`、`note=...` を取り出す。
- Markdown表を標準出力に出す。
- 入力ファイルが存在しない場合はエラーメッセージを出す。

実行例：

```sh
python3 labs/sandbox/python-log-formatter/format_log.py \
  labs/sandbox/python-log-formatter/sample.log
```

出力イメージ：

```text
| time | command | result | note |
| --- | --- | --- | --- |
| 2026-06-03T10:20:00 | git_status | ok | checked_worktree |
```

### 4. ラボノート作成 15分

`templates/lab-note.md` の型に沿って、`labs/2026-06-03_python-log-formatter.md` を作る。

必ず書くこと：

- 目的：PythonでローカルログをMarkdown表に整形する。
- 対象環境：自分のPC、ローカルファイル。
- 許可根拠：自分が所有するローカル環境。
- 範囲：`labs/sandbox/python-log-formatter/` のみ。
- 観察：入力ログの形式、出力Markdownの形式。
- 試したこと：実行したコマンド。
- 結果：変換できたこと、できなかったこと。
- まだ不明なこと：例外処理、CSV対応、日付パースなどから1つ。

### 5. Gitで差分確認 10分

```sh
git status
git diff -- labs/2026-06-03_python-log-formatter.md labs/sandbox/python-log-formatter/format_log.py
```

コミットするなら次を使う。

```sh
git add labs/2026-06-03_python-log-formatter.md labs/sandbox/python-log-formatter/
git commit -m "Add Python log formatter lab"
```

コミットしない場合でも、`git status` と `git diff` で差分確認までは完了条件に含める。
